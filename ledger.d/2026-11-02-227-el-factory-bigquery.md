## 2026-11-02 — EL Factory — a BigQuery warehouse and a GCP build without Postgres or TLC (#227, #307)

- Done: the TLC file sources are one package, `el_factory/tlc`, whose Flask blueprint (`/publication`, `/months`, `/retire`) and `/extract` the app serves only where the warehouse is a `FileLedger` (Postgres) and the package imports with pyarrow, now the `files` extra (#307 candidate 2).
  `warehouse_bigquery.py` loads BigQuery for `ELF_WAREHOUSE=bigquery` by load jobs into a staging table and one transaction per load, every query capped and every job labelled, behind a `bigquery` extra (google-cloud-bigquery 3.47.0).
  The Dockerfile's `bigquery` stage installs `requirements-bigquery.txt` and leaves out `warehouse_postgres.py` and `el_factory/tlc`; `platform/gcp/check_gcp_builds.py` covers it in `make gcp-validate`.
- Evidence: EL Factory's ruff and pytest pass (195 passed, 1 xfailed, the Compose warehouse and the BigQuery emulator up); `make gcp-validate` passes (82 tests; "gcp builds: dbt, semantic-agent, el-factory carry no Postgres package and no TLC or Postgres-only path").
  Images by content size: 107 MB for `WAREHOUSE=postgres`, as before the split, and 66 MB for `WAREHOUSE=bigquery`, whose build check finds no psycopg, pyarrow or TLC path.
  The postgres image served the tlc catalog and `/months` and extracted one synthetic page into the Compose warehouse; the bigquery image and a host run on the emulator extracted pages, replaced page 0 on a retry without duplicates, loaded a returns file twice to the same two rows, and answered 404 for tlc.
- Decisions: a staging table plus one multi-statement transaction rather than a partition `WRITE_TRUNCATE` (a page's scope is a run, an interval and a page, not a partition) or `MERGE` (the emulator runs neither its parameters nor `NOT MATCHED BY SOURCE` right); rows uploaded from memory rather than loaded from their `gs://` URI, so a file load keeps the generation it was asked for and the emulator, which cannot read fake-gcs, runs it; the TLC code in one subpackage that the `bigquery` stage's COPY leaves out, so the check fails on any TLC path outside it.
- Open: on some runs the emulator copies no row for a later page (marked xfail); EL Factory's Cloud Run service, bucket, service account and its BigQuery grants (Data Editor on `ds_source`, Job User), and `make gcp-images` pushing it, are #227's other half.
