# The rule's scoring as code, offline (#340)

Question (Q8, a slice of #333): can the eval score runs under [`RULE.md`](../RULE.md) before any arm runs, so #333 only has to collect answers?

## What was built and run

- [`services/semantic-agent/src/semantic_agent/bet_rule.py`](../../../../services/semantic-agent/src/semantic_agent/bet_rule.py): pure functions, no model and no warehouse.
  - `number_right`: every expected number carried, in the eval's own forms and tolerance (`carries`); a decline is never right, so an uncovered case is right only with its number.
  - `turn_outcome`: right, declined (no number, and the eval's `DECLINE` or `ASKS_WHICH` phrases), wrong (a number with a hedge from the set's list, or beside a decline), confident-wrong (a number with neither), unclear (no number and no decline: the judge's).
  - `run_outcome`, `arm_score` (accuracy, confident-wrong rate, pass^k, each group's accuracy, the unclear cases) and `paired_interval` (10,000 resamples, seed 325).
- `services/semantic-agent/tests/test_bet_rule.py`: 19 tests on scripted answers (`measured`, `make agent-test` 2026-11-03: 291 passed).
- The interval on 96 cases takes 0.06 s (`measured`, one call on synthetic scores).

## What it means for the verdict

- One refinement went into RULE.md before any run: a wrong number beside a decline ("no metric covers it, but summing every order gives …") is hedged, so wrong rather than confident-wrong; the rule's own wording already counted "not from governed definitions" as a hedge.
- The code decides every answer that states a number; only answers with neither a number nor a decline go to the judge, so the judge's share is measurable per arm in #333.

## Still unknown

- How many real answers land in `unclear`, and whether the hedge list misses common phrasings: #333's first runs show it, and a missed phrasing only moves an answer from wrong to confident-wrong, which the report lists case by case.
