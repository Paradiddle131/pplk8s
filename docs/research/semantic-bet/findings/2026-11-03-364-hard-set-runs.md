## What changed in the runner

- `bet_eval` and `probes/328_mcp_live.py` take `--set frozen|hard` (default the frozen set): `bet_eval.SETS` names each set's questions and files, so the hard set's runs go to `eval-hard-local.jsonl` and each live arm's `eval-hard-<arm>.jsonl`, its local report to `eval-hard-local.md`, and the frozen set's reader never takes an `eval-hard-*` log for an arm.
- [`eval.md`](../eval.md) holds one section per set ("Every arm on the frozen set", then "Every arm on the hard set"), each scored on its own with its own comparison against the managed best.
  One file rather than an `eval-hard.md` beside it: the issue's "Done when" names `eval.md`, and the report reads both sets' verdicts in one place; the frozen section is unchanged but for its headings, one level down (its anchors keep their names).
- The blind judge's cache stays one `judge.jsonl`: each new row names its `set`, a row naming none is the frozen set's (every row before #364), and each set's report applies only its own verdicts.
- The live runner now writes `eval.md` with the judge's cached verdicts applied, as `bet_eval` does (it wrote the unjudged logs before).
- Tests: `test_each_set_reads_only_its_own_logs_and_names_its_arms_by_the_file`, `test_the_hard_set_loads_by_name_with_its_groups`, `test_the_judge_cache_keeps_each_sets_verdicts_apart`, `test_eval_md_scores_each_set_in_its_own_section`, `test_each_set_logs_an_arm_to_its_own_file`.
- `probes/354_data_agent.py`: a chat whose connection fails (a reset, a timeout) is retried like a 429 and then left for a later pass; before, one `ConnectionResetError` (21:22Z) ended the whole `native-context` pass.
- `probes/354_data_agent.py`: an answer that is the project's daily BigQuery query quota refusing the agent's query (`QUOTA_ANSWER`) is a `daily_quota` failure that ends the pass, so a spent quota is never scored as the arm's answer (below).
