# The Claude Code setups through a strict headless runner (#387)

- Question: how do Claude Haiku, Sonnet and Opus answer the bet's sets through Claude Code when each run is one fresh headless session with only its setup's MCP tools, no shell, file or web tool, and every transcript audited?
- Owner, 2026-11-06, in a session: "running tools or commands in the terminal must be considered as cheating and must not be included in the results"; "we must check and enforce all these deterministically as much as possible"; "replace the old ones where they shared session with the new ones only when we have numbers ready".
- Setups (RULE.md § Changes since freezing, 2026-11-06T18:40Z): `cc-metricflow` mirrors `custom-metricflow`, `cc-native-mcp` mirrors `native-mcp`; tools and context verified in [the parity finding](2026-11-06-388-setup-parity.md).
- Every figure is `measured` (the answers, transcripts and logs named below) unless marked.

## The runner

- `probes/387_cc_strict.py run SETUP MODEL SET`: one `claude -p` (Claude Code 2.1.319, the owner's subscription, no API credits) per case-run, `--tools ""`, `--strict-mcp-config --mcp-config` (one server), `--allowedTools` (the served tools), `--permission-mode dontAsk`, `--setting-sources ""`, `--system-prompt-file` (the arm's own ADK instruction: `toolset_metricflow.INSTRUCTION`, `328_mcp_agent.INSTRUCTION`), `--no-session-persistence --input-format stream-json --output-format stream-json --verbose`; a conversation's turns are written one at a time, each after the previous `result` (two turns piped at once were answered as one: probe 2026-11-06T18:20Z).
- Servers: `semantic_agent.mcp_server` on 127.0.0.1:8765 with one bearer token per model (`SEMANTIC_MCP_CLIENTS`, so the audit table names `claude-code-strict-<model>`); `probes/387_mcp_guard.py` on 127.0.0.1:8766, Google's two MCP servers behind `native-mcp`'s cost guard (project pinned, a dry run under 10 MiB before every query), logging every call server side.
- A run aborts before its question when Claude Code's `init` tool list is not exactly the server's list, and the server's list must lie within the setup's declared tools (`semantic_agent.bet_tools`).
- Each answer line (`cc-strict/answers/<setup>-<model>-<set>.jsonl`) carries every real tool call with its result head and the audit; each full stream is kept gzipped (`cc-strict/streams/`).
- The audit (`audit`, tested in `tests/test_cc_strict.py`): (1) every `tool_use` is one of the served MCP tools: a failure is a test fault, which the scorer never logs (`bet_live` refuses it) and `387_cc_strict.py redact` redacts if ever logged; (2) each figure of the answer that no tool result of the run holds (dates, years and the question's own numbers left out, a rate matched as a percentage) is listed as uncited and scored as given; (3) a tool call written as text with no real call in that turn is flagged, and never counts as a figure source.
- Scored by `328_mcp_live.py --agent 387_cc_strict.py --arm <setup> --set <set> --runs 3 --no-canary` under the label `claude-code-strict (<model>)` (harness `claude-code-headless`, session `fresh per run`).

- The strict harness answers more than the shell-tool subagents on every set but Sonnet's frozen one, and the gain is almost all in the questions no single metric answers: Haiku's hard-v2 `composable` 67% against 27%.
- Most of that gain is the model computing a figure from metric results, against the instruction ("never compute, estimate or recall a figure yourself"): the audit finds a figure no tool result holds in 51 of Haiku's 106 right runs on hard-v2 (35 of 84 on hard, 26 of 197 on frozen), and in 37 of Sonnet's 85 on hard-v2. The rule scores the number, not the obedience, so these count as right, as they do for the ADK arm (Haiku's ADK `custom-metricflow` answers 79% of hard-v2's carried `composable` questions).
- Opus obeys the instruction: 3 of its 21 right runs carry a computed figure, and it answers 5% of `composable` questions, as the subagents did; so on this setup a stricter model scores lower, and the report shows it as the setup's property, not a fault.
- So #374's open question has an answer: the shell-tool subagents' decline habit was the harness. Reached as typed MCP tools in a fresh headless session, Haiku and Sonnet compose metrics the way the ADK agent does; reached through a shell command printing JSON, they declined.
- Covered questions are about where they were (Haiku 97% frozen) and confident-wrong stays low (2 to 7%).
- Tool calls a run: 2.6 to 3.6 on average; notional cost reported by Claude Code (the subscription pays, no credits): Haiku $1.54, Sonnet $25.74, Opus $5.77 for the whole pass.

## A scoring fault found and fixed (2026-11-06T19:50Z)

- The recorded-answer module first read every set's recordings of a setup and model; the hard set and hard-v2 share 43 questions, so while `cc-native-mcp` Sonnet's hard-v2 answers were not yet logged, its hard set was scored with some of them, and some runs with another run's answer.
- Found by the `bash_placeholder` refusal surfacing on the wrong run; 121 logged runs redacted as test faults in `redacted.jsonl` (never an edited log line), the module fixed to read only the scored set's file and to read logs through the overlay, and the runs scored again from their own recordings.
- `387_cc_strict.py redact` now checks every strict run in force against its own set's recording of that run: 0 mismatches over all 2,164 strict runs, and 0 runs outside their tools (`python -m semantic_agent.bet_tools`).
