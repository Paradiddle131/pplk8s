## The import, as documented (`stated`, [dbt import](https://docs.cloud.google.com/knowledge-catalog/docs/dbt-transfer), read 2026-11-03)

- Only `manifest.json` is required; MetricFlow's semantic models, metrics and saved queries come from it; `catalog.json` adds column types ("untyped columns" without it), `run_results.json` test outcomes, `sources.json` freshness.
- `gcloud` itself turns the artifacts into `dbt_metadata.jsonl`, uploads it to `--storage-uri` and starts the job; `--artifacts-path` is a local folder or a `gs://` prefix, so Cloud Shell can read the staged files; `--validate-only` builds and uploads the file without ingesting.
- It needs gcloud 586.0.0 or later; this cloud session has 570.0.0, and the $0 guard refuses every `gcloud dataplex` call here, `--help` included (`measured`), so the transform cannot be tried or sized from a wake.
- Entry types: `dbt-project`, `dbt-model`, `dbt-source`, `dbt-seed`, `dbt-snapshot`, `dbt-group`, `dbt-exposure`, `dbt-metric`, `dbt-macro`, `dbt-semantic-model`, `dbt-saved-query`, `dbt-test`; `reference` links to BigQuery tables only in the import's region; sources get no table link; no size cap is given beyond a per-aspect cap.

## What it means for the verdict
