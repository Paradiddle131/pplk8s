- The dataset guard refused 11 calls in 9 cases (10 queries naming `governed`, `gold` or `exposed`, which the catalog's search ranks first, and one `execute_query`); after each refusal it the agent rewrote the query over `silver` with the imported definition's arithmetic (status filters, ratios of sums, the last snapshot, the 2-day conversion window, deduplication by load).
- The cost guard also refused three queries whose dry run through the MCP tool returned no byte count (`the dry run refused the query: {}`); each of those cases went on to a query that ran.
- Every case began with `search_entries` and `lookup_context`, as in #328; answers cite the definitions ("per the approved definition", "per the view-to-cart rate metric's 2-day conversion window").
- The one miss is a definition the catalog holds outside a metric: the fiscal calendar lives in the time spine's columns and descriptions, and the agent read "fiscal 2026" as the calendar year.

## What it means for the verdict

- **Most of #328's win is the catalog's, not our governed tables'**: with only `silver` in reach, the agent turned the imported dbt definitions into correct SQL on 11 of 12 trap-heavy cases, so Knowledge Catalog's dbt import plus an agent that reads it carries the metric logic for the common shapes (filters, ratios of sums, non-additive balances, conversion windows) on one run.
- Governed tables still pay: they spare the agent a rewrite (9 of 12 cases reached for them first) and hold definitions that are not metrics, such as the fiscal calendar, which the agent missed once they were out of reach.
- What stays ours is unchanged: the compiled semantic query (#349) and the cost guard.
