# A data agent with and without Knowledge Catalog's imported metrics (#327)

Question (Q2): does a BigQuery data agent use the metric definitions Knowledge Catalog imported from dbt, compared with no context and with our generated context?
Status: answered for six trap questions, three runs each (the reference's third pass cut short): the agent never named or applied an imported metric, and the arm the import links to did no better than the arm it doesn't.

What the agents did:

- Every chat's stream shows one context step, `Retrieving context for 7 tables` (`bet-kc`, `bet-nokc`) or `for 17 tables` (`pplk8s-semantic`), then its own SQL over the tables; no stream named dbt, a metric entry, a semantic model or Knowledge Catalog (`mentions` empty in every `bet-kc` and `bet-nokc` row).
- The one trap the definitions decide, the average order value, `bet-kc` got wrong as often as `bet-nokc` (2 of 3 each), the same way and stated plainly, no hedge: `SELECT AVG(amount) ... FROM silver.orders WHERE order_date ...`, cancelled orders in, "the average order value was **€113.86** across 120 orders"; the imported `average_order_value_eur` (`revenue_eur` over non-cancelled `orders_total`, its `lookup_context` readable since 07:43Z) was never applied, and the right runs on both arms said they assumed cancelled orders out ("I assumed cancelled orders should be excluded").
  `pplk8s-semantic` answered 114.39 from `SUM(amount) / COUNT(*) ... AND status <> 'cancelled'`, the definition its generated context carries.
- On revenue, both catalog arms excluded cancelled orders on their own (the `status` values are in the data), and both added an unasked figure: `bet-kc` "(or €13,663.50 across all 120 placed orders)", `bet-nokc` a net of returns (€12,547.75).
- The ratio traps (cancellation rate, cost per lead) and the order-date return rate were right on every arm: on the lab's data the obvious SQL is the right SQL there, so these questions do not separate the arms (the frozen set's traps were measured on the eval fixture, not on these rows).

## What it means for the verdict

- **Importing the dbt project into Knowledge Catalog did not reach the data agent**: with the import linked to its tables, the agent answered as it did on unlinked copies, named nothing from the catalog, and missed the one definition-dependent trap exactly as the unlinked arm did.
  The owner's 2026-10-29 question, as #327's notes put it, gets the plain answer they asked for: on this lab, the agent never touched the imported metrics.
- What grounded the right answer is the context we put into the agent (`pplk8s-semantic`'s generated glossary, verified queries and instruction): the generated-context path of #310 stays the one that moves the number.
- The import still serves another consumer: an agent that calls `search_entries` and `lookup_context` itself (#328's ADK arm), where semantic search finds the right metric first (#326).
- Six questions with three runs is a directional answer, not the rule's comparison: the arms' rates on the whole frozen set are #333's.
